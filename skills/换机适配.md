# 换机适配 —— 换新电脑后点名跑一次，全库 skill 环境自动重新适配

> **触发**：换新电脑 / 重装系统后，对任意 AI 会话说一句："**跑换机适配**"（本文件是唯一入口）。
> **为什么存在**：skill 库随 GitHub 走遍所有电脑，但各 skill【运行记录】台账里写的都是当初某台机器的实测环境（解释器路径/依赖版本/参数），在新机器上大概率对不上。本文件 = 一次性把全库 skill 按新机器实况重新适配、把台账改过来——**改一次，之后所有 skill 的调用都干净**。

## 对 AI 的指令（被点名后照做，不用再问）

对 skills/ 目录下**每一个带【运行记录】台账的 skill**，依次执行四步：

> 纯提示词类 skill（如 grill-me/karpathy，无台账无依赖）**机器无关，自动跳过**——需要适配的只有实装过环境的那几个，工作量很小。

1. **探测**：跑该 skill 文档里的自检命令；没有自检命令的，按台账依赖清单逐个 `import` 探测。得出本机与台账的差异清单
2. **报告**：把差异汇总给用户——缺什么、打算装什么、用哪个解释器。**经用户点头才安装**（skill 里的禁装令管的是"环境已验证后的擅自变更"；新机器初始化必须走这里，由用户授权）
3. **实测**：环境就绪后，每个 skill 跑一次真实调用（选最轻量的方式），确认链路在本机通
4. **回写**：跑通的 skill，覆盖更新其【运行记录】——新条目**置顶、标注机器标识+日期**，旧机器记录往下留作历史；冲突以新记录为准

结束前给用户一张汇总表：每个 skill × 本机状态（✅ 可用 / ⚠ 装了什么 / ❌ 不可用原因）。确定本机用不上的，标 ❌ 并写明原因，别留着让后来的 AI 纠结。

## 给用户的提醒

- 新机器第一次跑完这张表，以后在该机器上照常点名用 skill 即可，不用再跑本文件
- 本文件随 skill 库走 GitHub，任何机器 clone 下来都有它
